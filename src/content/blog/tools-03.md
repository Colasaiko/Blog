第一次打开 sing-box 的 `config.json` 时，密密麻麻的 JSON 嵌套结构常让新手望而生畏。但只要理清 `inbounds`（入站）、`outbounds`（出站）、`route`（路由）和 `dns` 四大核心模块的分工，就能快速读懂并修改自己的配置规则。

当你第一次尝试在文本编辑器中打开 sing-box 的配置文件（通常名为 `config.json`）时，眼前映入眼帘的可能是一大串密密麻麻的大括号 `{}`、中括号 `[]`、双引号 `""` 以及各种各样的英文单词。这种看似复杂的代码结构往往会让刚入门的新手望而生畏。

但请不要担心，**你并不需要成为一名程序员才能看懂它**。配置文件本质上只是一份给 sing-box 内核阅读的“操作说明书”与“建筑蓝图”。只要理清了它的核心结构和模块逻辑，你就能轻松读懂它在做什么。

今天就来用最接地气的比喻，为你系统拆解 sing-box 配置文件的内部世界。

## 基本概念

什么是 sing-box 配置文件？

简单来说，**sing-box 配置文件是一个采用 JSON 格式书写的纯文本文件，它详细定义了 sing-box 如何接收流量、如何解析域名、如何分流决策以及如何将数据发送出去。**

### “现代机场调度中心”的比喻

为了让你直观理解配置文件的结构，我们可以把 sing-box 想象成一个**现代化的国际机场调度中心**：

1. **入站（Inbounds）**：相当于机场的**旅客出发/到达大厅与安检入口**。外部数据（你电脑、手机里的各类 App 流量）正是从这里进入调度中心。
2. **DNS 模块**：相当于机场的**问讯处与航班信息大屏**。当旅客不知道某个地名的具体经纬度（IP 地址）时，问讯处负责提供准确的导航信息。
3. **路由（Route）**：相当于机场的**海关与指挥控制塔**。它依据严格的规则（检查护照、机票目的地），决定每一位旅客该去往哪一个登机口。
4. **出站（Outbounds）**：相当于机场的**各大登机口与停机坪**。在这里停靠着飞往不同目的地的航班（直连通道、拦截黑洞、以及飞往各地的代理服务器节点）。
5. **日志（Log）**：相当于机场的**黑匣子与监控录像**。它默默记录下每一次调度操作，方便在出现问题时进行复盘排查。

所有这些模块的运作细则，全都被井井有条地记录在 `config.json` 这本总章程里。如果你想深入查阅每一个具体字段的官方语法规范，可以访问 [sing-box 官方文档](https://sing-box.sagernet.org/)。

## 进一步理解：五大核心模块深度拆解

在标准的 sing-box 配置文件中，最核心、最常见的通常包含以下五个顶层配置块：

```json
{
  "log": { ... },
  "dns": { ... },
  "inbounds": [ ... ],
  "outbounds": [ ... ],
  "route": { ... }
}
```

我们来逐一看看每个模块的具体职责：

### 1. `log`（日志模块）

日志模块负责控制 sing-box 运行时的记录输出。你可以设置日志的详细程度（Level）：
- `disabled`：关闭日志；
- `warn` / `error`：只记录警告与错误信息（适合日常平稳运行，节省存储）；
- `info` / `debug` / `trace`：详细记录每一个连接的建立、DNS 查询与规则匹配过程（适合刚搭建好或遇到故障时调试排查）。

### 2. `dns`（域名解析模块）

在访问任何网站之前，设备都需要将人类可读的域名（如 `google.com`）翻译成机器可读的 [IP 地址](/blog/guide-02/)。sing-box 拥有非常强大的内置 DNS 服务器，可以实现：
- **防污染与分流解析**：国内域名使用国内公共 DNS 解析以获取最快的直连 IP；海外域名通过加密通道（如 DoH/DoT）解析，有效杜绝 DNS 污染；
- **Fake-IP 机制**：由 sing-box 本地直接分配一个临时虚拟 IP，跳过本地解析等待时间，极大加快网页首次打开的响应速度。

### 3. `inbounds`（入站模块）

入站模块决定了 sing-box 以何种方式捕获设备流量。常见类型包括：
- **`tun` 模式**：在操作系统中创建一张虚拟网卡，自动接管全设备的所有网络流量，无需为每个软件单独设置代理，对新手最省心；
- **`mixed` 模式**：在本地开启一个混合代理端口（例如 `127.0.0.1:7890`），同时兼容 HTTP 和 SOCKS5 代理协议；
- **`tproxy` / `redirect`**：主要用于 Linux 软路由网关环境下的透明代理。

### 4. `outbounds`（出站模块）

出站模块定义了所有数据流出的“出口”。出站通常分为三大类：
1. **基础动作出站**：
   - `direct`：直连出口，数据不经过任何代理，直接通过你本地的[网络线路](/blog/guide-01/)发送；
   - `block`：拦截出口，直接丢弃数据包（常用于屏蔽广告和追踪器）。
2. **实际代理节点**：
   - 填入具体的远程服务器参数（如 Shadowsocks、VMess、VLESS、Trojan、Hysteria 2 等[网络协议](/blog/guide-05/)及对应的密钥、端口）。
3. **逻辑策略组（Selector / URL-Test）**：
   - `selector`（手动选择）：在客户端界面上生成一个下拉菜单，允许你手动切换节点；
   - `urltest`（自动测速）：后台定期对组内节点发起测速，自动将流量分发给当前延迟最低、最稳定的节点。

### 5. `route`（路由模块）

路由模块是整个配置文件的“智能大脑”。它包含一套严格的规则列表（Rules）与规则集（Rule Sets）：
- 它会按照自上而下的顺序依次检查数据包的域名、IP、端口或来源应用；
- 一旦某条规则命中，就将流量指派给指定的出站标签（Outbound Tag）；
- 如果所有规则都没匹配上，则交给最后的 `final` 默认出站处理。

## 实际应用

在日常生活中，普通用户通常会怎样与 sing-box 配置文件打交道？

### 1. 一键订阅导入（全自动化）

绝大多数普通用户在日常使用中，**并不需要手写整个配置文件**。你只需在图形化客户端中填入服务商提供的订阅链接，客户端会自动从云端下载并转换成合规的 `config.json` 文件。

### 2. 局部微调与个性化定制

当你掌握了配置文件的基本结构后，你可以轻松实现一些高级定制：
- 想要彻底屏蔽某些视频软件的开屏广告？在 `route.rules` 中添加针对该广告域名的 `block` 规则；
- 想要特定流媒体只走香港节点？将对应的域名规则指向名为 `HK-Selector` 的出站组；
- 想要某款游戏完全直连不走代理？添加一条游戏进程名或端口的 `direct` 规则。

### 3. 配置文件语法校验

在手动修改 JSON 文件时，如果不小心多打了一个逗号或者少了一个引号，就会导致 sing-box 无法启动。熟练的用户会使用 VS Code、在线 JSON 校验工具（JSON Linter）或者直接运行 `sing-box check -c config.json` 命令来验证语法正确性。

## 常见误区

### 误区一：不手写 JSON 就无法体验 sing-box 的强大功能
**纠正**：完全是误解。现代桌面和手机客户端（如 Karing、GUI.for.SingBox 等）提供了非常完善的可视化操作界面。你可以像使用其他成熟客户端一样通过点击和开关完成所有配置。

### 误区二：JSON 文件里的标点符号可以随意写
**纠正**：JSON 是一种语法要求极其严苛的数据格式。所有的键名和字符串值必须用英文字符的双引号 `""` 包裹（单引号会报错）；列表项之间必须用逗号 `,` 分隔，且最后一项后面不能有多余的尾随逗号。

### 误区三：出站 tag 名称与路由 rules 可以随意命名
**纠正**：在出站模块定义的每个节点或策略组都有一个唯一的 `tag`（例如 `"tag": "Proxy-Node"`）。在路由模块编写规则时，指定的 `"outbound": "Proxy-Node"` 必须与之一字不差（严格区分大小写）。如果名称拼错，sing-box 就会因为找不到对应的出口而报错。

## 总结

sing-box 配置文件看似复杂的代码外表下，蕴含着极其清晰、优雅的模块化逻辑。

- **`inbounds`** 负责迎客入站；
- **`dns`** 负责寻址导航；
- **`route`** 负责智能分流；
- **`outbounds`** 负责承运出港；
- **`log`** 负责全程记录。
