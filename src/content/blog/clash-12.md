打开 Clash 控制面板，你通常会看到「🚀 节点选择」、「🎥 国际媒体」、「🤖 自动测速」等各种卡片分类，这些在技术上被称为**代理组（Proxy Groups / 策略组）**。它不仅能将海量节点按用途有序归类，还支持节点故障自动切换、测速优选和多线路负载均衡。

如果你第一次打开 Clash（如 Clash for Windows 或 ClashX）的代理控制面板（Proxies），你可能会被眼前密密麻麻的一堆节点和一排排的按钮给震慑住。你会看到类似于“🚀 节点选择”、“🎥 流媒体解锁”、“🍎 苹果服务”、“🤖 自动测速”等各种分类框，每个框里面又包含了许多国家的节点。

这些分类框，就是我们今天要详细探讨的主角——“代理组”。理解了代理组的概念，你不仅能看懂那些复杂的控制面板，还能随心所欲地定制专属于你自己的网络调度中心。

## 基本概念：什么是代理组？

为了讲清楚代理组，我们先来复习一下前一篇文章中的“分流”。
分流系统的作用是把不同去向的流量分开，比如把 YouTube 的流量单独抽离出来。
但是，抽离出来之后呢？你需要指定一个**具体的代理节点**去处理这部分流量。

如果你的机场只有 2 个节点（比如一个美国，一个日本），那事情很简单，你直接告诉客户端：“YouTube 流量交给美国节点”。
但现实中，绝大多数机场的订阅包含几十甚至上百个节点（香港 01、香港 02、美国 01...台湾 05 等等）。如果你把流量直接绑定死在某一个具体的节点（比如“美国 01”）上，一旦这个节点出现故障掉线了，你的 YouTube 就彻底看不成了，你需要进配置代码里去手动修改绑定的节点，这简直是反人类的设计。

**为了解决这个问题，“代理组（Proxy Group）”应运而生。**

**代理组，本质上就是一个“装满了节点的篮子”，并且赋予了这个篮子一种特殊的“挑选机制”。**

在分流系统中，我们不再把流量指派给某一个具体的节点，而是指派给某一个“代理组”（篮子）。当流量进入这个代理组时，代理组会根据它自身设定的逻辑，从篮子里成百上千个节点中，挑选出一个最合适的节点，去完成这次网络请求。

这种设计将“分流规则”和“底层节点”完美地解耦了。节点坏了没关系，代理组会自动或让你手动从篮子里挑另外一个能用的就行。

## 进一步理解：代理组的常见类型

不同种类的“篮子”，有着不同的挑选节点的机制。在 Clash 等现代代理软件中，代理组主要有以下几种最经典的类型：

### 1. 手动选择组（Select / Manual）
这是最常见、最直观的代理组。
- **机制：** 这个组会把你所有的节点列出来，像菜单一样排开。**它完全听从你的指挥，你用鼠标点击或者手指选中了哪一个节点，它就固定使用哪一个节点，直到你再次手动修改为止。**
- **界面表现：** 在 Clash 中，这种组的图标通常是一个带有单选框的列表。
- **典型应用：** 通常作为主力的“PROXIES”或“节点选择”组。你的大部分常规代理流量都会导向这个组，你可以根据当天哪个国家网速快，手动点选那个国家的节点。

### 2. 自动测速组 / 自动回退组（URL-Test / Fallback）
这是懒人必备的高级代理组，极具智能。
- **URL-Test（自动测速）机制：** 这个组会在后台每隔一段时间（比如 300 秒），自动拿着篮子里的所有节点去访问一下指定的测速网站（通常是谷歌的连通性测试网页 `http://www.gstatic.com/generate_204`）。测试完之后，**它会自动帮你选中那个延迟最低、响应最快的节点。** 流量进入这个组，永远享受最快的速度。
- **Fallback（故障转移 / 自动回退）机制：** 这个组也会后台测速，但它的逻辑是按顺序来的。它默认使用列表里的第一个节点。如果它发现第一个节点挂了（测速超时），它就会自动切换到第二个节点，第二个也挂了就切第三个。一旦第一个节点恢复了，它又会自动切回去。这是保证网络高可用性（绝不断网）的神器。
- **典型应用：** 把所有香港节点放进一个 URL-Test 组，命名为“🇭🇰 自动优选香港”，这样你永远连接的是当前最快的一个香港节点。

### 3. 负载均衡组（Load-Balance）
这是一种进阶的高端玩法。
- **机制：** 这个组不固定使用某一个节点。当有一大批网络请求涌入这个组时，它会像发牌一样，把请求均匀地散布给篮子里的所有活跃节点（或者根据特定的哈希算法分配）。比如你同时下载包含 10 个线程的文件，它会让节点 A 负责 2 个线程，节点 B 负责 3 个线程。
- **典型应用：** 适合你拥有多个优质且延迟相近的节点时，用来突破单一节点的宽带速度上限，实现“多路并发并发下载”。但注意，这对很多需要固定 IP 的网站（如论坛登录、网银）极度不友好，容易被判为异地频繁登录。

### 4. 嵌套代理组（组中组）
这是代理组最强大也是最复杂的一面——**一个代理组的篮子里，不仅可以装节点，还可以装其他的代理组！**

举个例子：
你创建了一个手动选择组叫“🚀 主力节点”。里面装了所有的国家节点。
你又创建了一个手动选择组叫“🎥 Netflix 解锁”。在这个组里，你不仅放了几个特定的新加坡节点，**你还把上面那个“🚀 主力节点”也作为一个选项放了进去！**

这样有什么好处呢？
当你想专门为 Netflix 指定新加坡节点时，你在“🎥 Netflix 解锁”组里点选新加坡节点；
当某天你发现你常用的“🚀 主力节点”也能看 Netflix 时，你就可以在“🎥 Netflix 解锁”组里，点选“🚀 主力节点”这个选项。这样，Netflix 的流量就会顺着层级，交给主力节点去处理。
这种嵌套设计，极大地提升了配置的灵活性和逻辑层级感。

## 实际应用：解析经典的面板布局

为了让你彻底搞懂，我们来剖析一个极其经典且常见的 Clash 面板布局（这通常是著名的 ACL4SSR 规则集的默认布局）。

当你在客户端看到以下代理组时，它们的内部逻辑通常是这样的：

1. **PROXIES (🚀 节点选择) [手动组]**
   - **作用：** 系统的“总控台”。绝大多数未被特殊分类的海外网站（如 Google, Twitter）的流量都会流向这里。
   - **内容：** 包含了你机场的所有单体节点，外加几个自动组。你在这里选什么，大部分外网流量就走什么。

2. **Apple (🍎 苹果服务) [手动组 / 嵌套组]**
   - **作用：** 专门接管来自 Apple 域名（如 iCloud 同步）的流量。
   - **内容：** 选项可能包括 DIRECT（直连），以及嵌套了“🚀 节点选择”。如果你发现 iCloud 同步很慢，你可以把它从 DIRECT 切换到走代理，反之亦然。

3. **Netflix (🎥 奈飞节点) [手动组]**
   - **作用：** 分流系统已经把奈飞的流量指派到这里了。
   - **内容：** 里面全是能够解锁奈飞原生版权的特殊节点（如特定的台湾、新加坡节点）。由于它独立于“总控台”，你在这里选新加坡节点看剧，完全不影响你在总控台选美国节点刷推特。这就是分流+代理组结合的最完美的日常体现。

4. **Telegram (📲 电报信息) [自动测速组]**
   - **作用：** 电报需要极低的延迟和极高的稳定性。
   - **内容：** 将所有高质量节点放入 URL-Test 测速机制中。无论什么时候打开电报，它都自动走当前延迟最低的那个节点，保证消息秒回，无需你手动干预。

5. **AdBlock (⛔️ 广告拦截) [手动组]**
   - **作用：** 接管所有被识别出的广告流量。
   - **内容：** 默认选中的是 REJECT（拒绝）。当然，如果你遇到某个网站因为误杀广告导致网页错位，你可以临时把这个组切换成 DIRECT（放行），排查完毕后再切回 REJECT。非常人性化。

## 常见误区

在操作代理组时，新手经常会陷入以下迷惑行为：

### 误区一：在子代理组里乱选导致逻辑死循环
由于存在“嵌套代理组”，逻辑层级关系很重要。假设组 A 嵌套了组 B，组 B 又嵌套了组 C。如果你在组 A 里选了组 B，在组 B 里选了组 C，然后在组 C 里又不小心选回了组 A……这种极端的嵌套死循环会导致流量在客户端内部打转，引发软件崩溃或该类网站彻底断网。好在现代客户端会尽量避免这种配置的生成，但手动乱选仍有可能引发逻辑混乱。**保持清晰的主次层级意识很重要。**

### 误区二：盲目迷信自动测速组（URL-Test）
新手往往觉得“自动帮你选最快的”一定最好，于是把所有的流量都指派给自动测速组。
这会带来两个严重后果：
第一，自动组为了知道哪个节点快，会频繁在后台每隔几分钟对几十个节点发起测速请求。这不仅极度耗电，还会消耗机场套餐里的流量。
第二，你的公网 IP 会频繁跳动。可能前一分钟你被分配到香港节点，后一分钟日本节点变快了，系统自动把你切到了日本。这种高频的 IP 跳跃，对于许多有风控的账号系统（如推特、Facebook 甚至游戏）是致命的，极容易导致账号被封禁。**除非是针对特定应用（如电报），否则日常网页浏览建议老老实实使用固定国家的手动组。**

### 误区三：节点列表前的数值越小越好？
在手动选择组的界面上，每个节点旁边通常会显示一个数字（如 `150ms`, `500ms`）。很多新手认为一定要选数字最小的那个。其实，这个延迟往往指的是你的本地网络到代理服务器（比如香港）的 Ping 延迟，并不代表真实下载速度或网页加载速度。有时候一个延迟 200ms 的美国节点，其视频加载速度可能远远超过一个延迟 50ms 但已经拥堵不堪的香港节点。**延迟仅供参考，实际体验才是王道。**

## 总结

如果把“分流规则”比作是将各种快递包裹分拣开的传送带，那么“代理组”就是传送带尽头的一个个发货车队。

你可以拥有一个固定路线的老司机车队（手动选择组），你可以拥有一个谁跑得快就用谁的出租车队（自动测速组），你甚至可以拥有一个能把货物拆分同时运送的高铁编组（负载均衡组）。

正是因为有了代理组的存在，我们在面对几十上百个节点时，才不会显得手忙脚乱。我们可以针对流媒体、聊天软件、游戏、网页等不同类型的需求，配置出截然不同的调度策略，从而构建出一个全自动、高可用、极致个性化的国际网络环境。

至此，我们已经从“工作模式”、“分流规则”一路讲到了“代理组”。你已经掌握了现代代理客户端最核心的运作逻辑和概念体系。接下来，就到了实战阶段：如何将这些复杂的配置完美地装进你的软件里？请继续阅读我们的下一篇指南：《Clash 如何导入配置？》。
