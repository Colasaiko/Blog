## 基本概念：什么是 Display Filter？

### 1. 显示过滤器的定义

**显示过滤器（Display Filter）** 是 Wireshark 提供的一种强大的后置查询与筛选引擎。

它的核心机制是：在网卡已经将所有数据包完整捕获并保存在内存或文件中之后，用户通过在顶部输入特定的过滤表达式，**动态改变界面上的展示视角**——只展示满足条件的数据包，而将不关心的背景噪音数据包临时隐藏起来。

### 2. 生动比喻：Excel 筛选器与全景监控录像回放

我们可以打个比方：

- **抓包过程**：相当于商场里的多路 4K 监控摄像头，24 小时不间断录下所有人进进出出的一举一动（所有数据包都被忠实完整地存盘）。
- **显示过滤器**：相当于监控室里的**智能搜索功能**。如果你输入 `只看穿红衣服并且在下午 3 点进店的顾客`，监控画面就会瞬间过滤掉无关路人，精准呈现目标画面。
- **最关键的是**：隐藏并不等于删除。只要你清空搜索框，所有原始数据包依然毫发无损地保留在后台。

### 3. Display Filter（显示过滤）vs Capture Filter（捕获过滤）

很多新手在初学 Wireshark 时，容易把“显示过滤器”与“捕获过滤器”混淆。这两者有本质的区别：

| 对比维度 | 捕获过滤器（Capture Filter） | 显示过滤器（Display Filter） |
| :--- | :--- | :--- |
| **生效时机** | 数据包被抓取进内存**之前** | 数据包已经捕获保存**之后** |
| **底层语法** | 基于底层的 BPF 语法（如 `host 1.1.1.1 and port 80`） | Wireshark 专有高级语法（如 `ip.addr == 1.1.1.1 && tcp.port == 80`） |
| **可逆性** | **不可逆**：未匹配的数据包在网卡层直接丢弃，无法找回 | **完全可逆**：随时修改条件，原始数据包始终完整无损 |
| **协议支持度**| 仅支持基本的网络层、传输层协议过滤 | 支持数千种协议及数万个细分字段的深度解析匹配 |
| **推荐新手使用**| 仅在超高带宽、长时间抓包防爆内存时使用 | **日常分析绝对主力，强烈推荐优先使用** |

## 进一步理解：Display Filter 的核心语法结构

Wireshark 的显示过滤语法设计得非常符合自然逻辑，主要由以下四部分构成：

```
[ 协议 / 字段名 ]  +  [ 比较操作符 ]  +  [ 目标数值 / 字符串 ]
例如:  ip.addr        ==              192.168.1.1
```

### 1. 协议级过滤（最简单直接）
只需在过滤框中直接输入协议的小写名称，即可过滤出该协议的所有流量：
- `dns`：仅显示所有 DNS 域名解析相关的数据包；
- `http`：仅显示明文 HTTP 请求与响应；
- `tcp` 或 `udp`：仅显示对应的传输层协议数据包；
- `arp`、`icmp`、`tls`、`ssh`、`dhcp`：同样支持一键协议直达。

### 2. IP 地址与端口过滤
- `ip.addr == 192.168.1.1`：显示源 IP 或目的 IP 为 `192.168.1.1` 的所有数据包；
- `ip.src == 192.168.1.100`：仅筛选**发送方（源地址）**为该 IP 的包；
- `ip.dst == 8.8.8.8`：仅筛选**接收方（目的地址）**为该 IP 的包；
- `tcp.port == 80`：筛选 TCP 端口为 80（HTTP）的数据包；
- `udp.port == 53`：筛选 UDP 端口为 53（DNS）的数据包。

### 3. 比较操作符与逻辑连接词
Wireshark 既支持符号表达，也支持英文缩写表达：

| 逻辑类型 | 符号表达 | 英文缩写 | 示例 |
| :--- | :--- | :--- | :--- |
| **等于** | `==` | `eq` | `ip.src == 10.0.0.1` |
| **不等于** | `!=` | `ne` | `tcp.port != 443` |
| **大于 / 小于** | `>`, `<` | `gt`, `lt` | `frame.len > 1000` |
| **逻辑与（并且）**| `&&` | `and` | `ip.addr == 1.1.1.1 && tcp.port == 80` |
| **逻辑或（或者）**| `\|\|` | `or` | `http \|\| dns` |
| **逻辑非（取反）**| `!` | `not` | `!arp`（排除所有 ARP 广播包） |

### 4. 字符串包含与模式匹配
- `contains`（包含特定字符串）：`http.request.uri contains "login"`（筛选 URL 中包含 login 的请求）；
- `matches`（正则表达式匹配）：`http.user_agent matches "(Chrome|Safari)"`。

### 5. 贴心的“交通灯”变色输入框
在 Wireshark 顶部输入过滤器时，输入框的背景颜色会实时反馈语法的正确性：
- 🟢 **绿色背景**：语法完全正确，放心按回车执行；
- 🔴 **红色背景**：存在语法错误或拼写错误的字段名，无法执行；
- 🟡 **黄色背景**：语法合法，但可能存在逻辑陷阱（例如对多值字段使用了容易误解的比较条件）。

## 实际应用：日常排障高频过滤秘籍与小技巧

掌握以下几个黄金过滤组合，能覆盖你日常 90% 以上的抓包分析需求：

### 1. 经典排障场景速查表

| 排障目标 | 推荐显示过滤表达式 | 作用说明 |
| :--- | :--- | :--- |
| **排查特定主机通信** | `ip.addr == 192.168.1.50 && tcp.port == 8080` | 锁定特定设备与特定业务端口的所有交互 |
| **快速发现网络丢包重传**| `tcp.analysis.flags` | 自动筛选出所有重传、重复 ACK、乱序等异常标记 |
| **排查 HTTP 报错** | `http.response.code >= 400` | 一键拉出所有 4xx（客户端错误）和 5xx（服务端错误）|
| **仅看 HTTP POST 提交** | `http.request.method == "POST"` | 快速定位表单提交、接口调用请求 |
| **查找 DNS 解析异常** | `dns.flags.rcode != 0` | 筛选所有未成功解析的 DNS 错误应答 |
| **查看 HTTPS 访问域名** | `tls.handshake.type == 1` | 捕获 Client Hello 报文，查看客户端正在发起的 SNI 目标网站 |

### 2. 效率神器：“右键一键生成过滤器”

新手完全不需要死记硬背成百上千个字段名称！Wireshark 提供了一个极其便捷的功能：
1. 在中间面板（协议详细树区）找到你关心的任何字段（比如某个 IP、某个端口或某个响应码）；
2. **鼠标右键点击该字段**；
3. 选择 **Apply as Filter（作为过滤器应用） -> Selected（选中）**；
4. Wireshark 就会自动在顶部输入框中精准填入该字段的标准语法并立刻执行过滤！

## 常见误区：初学者最常踩的语法深坑

### 误区一：对 `!=` 运算符的逻辑误解（最经典大坑）
很多新手想“排除掉 IP 为 192.168.1.1 的数据包”，于是写下：`ip.addr != 192.168.1.1`。
结果发现列表中依然出现了大量的 `192.168.1.1`！

**原因解析**：
一个 IP 数据包同时包含 `ip.src`（源 IP）和 `ip.dst`（目的 IP）两个字段。Wireshark 在执行 `ip.addr != X` 时的逻辑是：“只要源 IP **或者** 目的 IP 中有一个不等于 X，就判定为匹配”。当源 IP 是 192.168.1.1 但目的 IP 是 8.8.8.8 时，因为 8.8.8.8 != 192.168.1.1，该包依然会被判定为符合条件！

**正确写法**：必须使用取反逻辑：`!(ip.addr == 192.168.1.1)`。

### 误区二：在显示过滤框里输入捕获过滤语法
比如输入 `src host 10.0.0.1`，输入框会立即变红报错。
记住：`src host ...` 是捕获过滤器（BPF）的语法；在显示过滤器中，正确的写法是 `ip.src == 10.0.0.1`。

### 误区三：“过滤后数据变少了，我刚才抓的数据是不是丢了？”
**纠正**：显示过滤器是完全**非破坏性**的。只需点击过滤框右侧的清空按钮（或按 Backspace 清空输入框后按回车），原本捕获的所有数据包会立即完整恢复显示。
