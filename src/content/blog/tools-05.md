刚接触 sing-box 时，最容易让人头疼的往往不是软件本身，而是配置和日志里层出不穷的专业名词：Inbound、Outbound、TUN 模式、Fake-IP、流量嗅探……把这些核心概念搞清楚，后面的配置和排错才会真正变得顺手。

然而，对于刚刚进入这个领域的新手来说，在查看客户端界面、阅读技术教程或者排查连接日志时，常常会被各种扑面而来的专业英文缩写和术语搞得一头雾水：“什么是 Inbound 和 Outbound？”、“TUN 模式和系统代理有什么区别？”、“Fake-IP 和流量嗅探又是干什么的？”

为了帮助你彻底扫清这些术语障碍，今天就来作为一份**新手必备的 sing-box 术语速查词典**，用最形象的比喻和通俗的大白话，为你一一拆解这些核心概念。

## 基本概念：四大核心基础术语

无论 sing-box 的配置多么复杂，它的骨架始终建立在以下四个最基础的术语之上：

### 1. Inbound（入站）
- **定义**：流量进入 sing-box 的“入口”。
- **通俗解释**：相当于收费站的“入口通道”。你的操作系统、网页浏览器或手机 App 产生的所有网络请求，首先都要通过某一个 Inbound 送进 sing-box 核心内部。
- **常见类型**：`tun`（虚拟网卡全局捕获）、`mixed`（本地 HTTP/SOCKS5 混合代理端口）、`tproxy`（Linux 透明代理）等。

### 2. Outbound（出站）
- **定义**：流量离开 sing-box、发往外部目的地的“出口”。
- **通俗解释**：相当于机场的“登机口”。数据在经过内部处理后，最终必须通过某一个出站通道发送出去。
- **常见类型**：
  - `direct`（直连）：不走任何代理，直接通过你本地的[网络线路](/blog/guide-01/)连接目标；
  - `block`（拦截）：直接丢弃数据包（用于屏蔽广告）；
  - 具体的代理协议节点（如 Shadowsocks、VMess、Trojan、Hysteria 2 等[网络协议](/blog/guide-05/)）；
  - 策略组（如 `selector` 手动选择、`urltest` 自动测速）。

### 3. Route（路由）
- **定义**：连接 Inbound（入站）与 Outbound（出站）的智能分流中枢。
- **通俗解释**：相当于机场的“调度控制塔”。它依据预先设定的规则列表（Rules），检查每个进入 Inbound 的数据包（看它的目标域名、IP 或应用），然后决定将其分发到哪一个 Outbound 出口。

### 4. Node / Endpoint（节点 / 终端）
- **定义**：提供实际网络代理中转服务的远程服务器。
- **通俗解释**：分布在不同国家和地区的服务器实体。你的加密数据会先发送到这个节点，再由该节点转发访问最终的目标网站。

如果你想对照官方的技术规范查阅每一个术语的标准定义，可以访问 [sing-box 官方文档](https://sing-box.sagernet.org/)。

## 进一步理解：进阶技术与功能术语

除了基础的骨架术语，在日常使用和性能调优中，你还会经常遇到以下关键技术概念：

### 1. TUN 模式（虚拟网卡模式）
- **通俗解释**：在你的操作系统中创建一张“虚拟网卡”。
- **作用**：传统的系统代理（System Proxy）只能接管支持代理协议的浏览器等软件，而很多命令行工具、游戏客户端或者后台服务并不遵守系统代理。开启 TUN 模式后，系统所有底层的网络流量都会被强制导流进虚拟网卡，实现全设备、无死角的代理接管。

### 2. Rule-Set 与 SRS（规则集与二进制规则）
- **通俗解释**：独立打包的高速规则数据库。
- **作用**：sing-box 创新地将海量的域名列表（Geosite）和 IP 列表（GeoIP）预先编译成轻量级的二进制文件（`.srs`）。相较于传统的纯文本规则，SRS 规则集具有加载时间短、内存占用低、毫秒级快速匹配的巨大优势。

### 3. Fake-IP（伪装虚拟 IP / 快速应答机制）
- **通俗解释**：由 sing-box 本地直接“秒回”一个临时的虚拟 IP 地址。
- **作用**：通常情况下，打开网页需要先向 DNS 服务器发起查询，等待返回真实 IP 后才能连接，这会产生额外的往返延迟，甚至可能遭遇 DNS 污染。在 Fake-IP 模式下，sing-box 本地立即返回一个私有伪装 IP（如 `198.18.0.x`），设备拿着这个 IP 发起请求，sing-box 捕获后直接把真实域名交给远端代理服务器去解析和连接，极大加快了首次加载速度并杜绝了本地 DNS 污染。

### 4. Sniffing（流量嗅探 / 域名识别）
- **通俗解释**：在数据包流经时，拆开外包装“瞄一眼”里面真正的访问域名。
- **作用**：当某些应用直接使用裸 [IP 地址](/blog/guide-02/)发起连接时，sing-box 无法直接通过域名规则进行分流。开启嗅探功能后，内核可以在 TLS 握手阶段读取 SNI 字段或 HTTP 头部的 Host 字段，还原出真实的访问域名，从而让域名分流规则精准生效。

### 5. Multiplex / Mux（多路复用）
- **通俗解释**：把多辆小汽车合并装上一趟“高铁列车”。
- **作用**：通常每次网络请求都需要经历 TCP 握手和 TLS 加密握手。开启 Mux 后，多个并发的 TCP 连接可以共享同一条底层的物理通道，省去重复握手的延迟，非常适合高并发浏览网页的场景。

### 6. Selector 与 URL-Test（选择器与自动故障转移）
- **Selector（手动选择组）**：在客户端图形界面上呈现为一个下拉切换菜单，由用户根据需要手动切换节点（例如在“香港 01”与“日本 02”之间切换）。
- **URL-Test（自动测速组）**：客户端在后台定期向指定的测速网址发起微型测速，自动将流量切换至当前延迟最低、连接最通畅的节点；当某个节点发生故障中断时，自动无缝切换到备用节点（Fallback）。

### 7. TProxy（透明代理）
- **通俗解释**：在 Linux 系统底层悄无声息地重定向流量，连客户端自己都察觉不到。
- **作用**：主要应用于软路由和旁路网关环境。局域网内的手机、电视、电脑不需要进行任何配置，只要连上 Wi-Fi，数据在经过软路由时就会被 TProxy 模块自动截获并进行分流。

## 实际应用：利用术语快速排查日常问题

了解这些术语不仅能帮助你读懂教程，更能让你在遇到网络问题时快速定位原因：

| 遇到问题 | 涉及的核心术语 | 排查与解决思路 |
| :--- | :--- | :--- |
| **玩国服游戏时延迟突然飙升或丢包** | TUN 模式 / Direct 直连规则 | 检查 TUN 模式下是否为游戏进程或局域网私有 IP（`ip_is_private`）配置了 `direct` 直连规则。 |
| **访问特定 AI 服务提示地区不支持** | Fake-IP / Sniffing / Selector | 检查该域名的分流规则是否精准绑定到支持该地区的 Outbound 节点，并确认开启了流量嗅探以避免 IP 误判。 |
| **低配软路由运行一段时间内存暴涨** | SRS 规则集 vs 纯文本规则 | 将过大冗余的纯文本规则替换为官方编译的 `.srs` 二进制规则集，大幅降低内存开销。 |
| **打开网页响应慢，但测速带宽很高** | DNS 解析延迟 / Fake-IP | 尝试开启 sing-box 的 Fake-IP 模式，跳过本地漫长的 DNS 解析等待。 |

## 常见误区

### 误区一：开启 Mux（多路复用）能让下载速度直接翻倍
**纠正**：Mux 的核心价值在于**减少频繁新建连接的握手延迟**，对于浏览图片多、并发请求多的网页非常有效。但在大文件下载或弱网高丢包环境下，所有数据挤在单一通道里可能发生“队头阻塞”，反而可能导致单线程下载速率波动。

### 误区二：Fake-IP 会导致隐私泄露给访问的网站
**纠正**：Fake-IP 只是在你的电脑和本地 sing-box 核心之间使用的临时内部代号。当数据发往远端服务器时，sing-box 已经将其还原为真实域名并通过加密隧道传输，目标网站根本看不到这个本地虚拟 IP。

### 误区三：TUN 模式等同于传统 VPN
**纠正**：TUN 模式虽然借用了与 VPN 相同的虚拟网卡技术，但传统 VPN 通常是将全设备所有流量一股脑推向单一网关；而 sing-box 在虚拟网卡之后拥有强大的**规则引擎（Route）**，能够实现智能的精细化分流。

## 总结

sing-box 的世界虽然涉及诸多技术名词，但只要理清了核心脉络，一切都会变得十分清晰：
- **基础骨架**：Inbound（进） $\rightarrow$ Route（判） $\rightarrow$ Outbound（出）；
- **高级辅助**：TUN 负责全局接管，Fake-IP 负责极速寻址，Sniffing 负责精准识别，SRS 负责高效匹配。
