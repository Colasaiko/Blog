默认情况下，Tailscale 只会在你访问网内设备时走加密隧道，日常网页流量依然直连。但在公共 Wi-Fi 等不安全环境下，或者需要借用家中宽带 IP 上网时，通过开启 **Exit Node（出口节点）**，就能将所有网络流量先加密转发到指定设备，再代为访问公网。

默认情况下，Tailscale 采用的是**分流模式（Split Tunneling）**：
- 当你访问加入 Tailnet 的其他设备（比如家中 NAS、办公室电脑的 `100.x.y.z` IP）时，流量会经过高强度加密的点对点隧道；
- 但当你正常浏览网页（如打开百度、微博、新闻资讯）时，流量依然直接走你当前所连接的本地 Wi-Fi 或手机移动网络。

但在现实生活中，我们经常会遇到这样的场景：
- 你在火车站、机场、咖啡馆连接了没有密码的公共公共 Wi-Fi，担心账号密码被同一局域网下的黑客窃听或遭遇 DNS 劫持；
- 你人在外地出差，但某些特定业务或流媒体服务限制了只能从你家里的固定宽带 IP 访问；
- 你希望所有上网流量都能借道一台处于安全网络环境中的云服务器发出。

这时候，Tailscale 的一项杀手级功能就派上用场了——**Tailscale Exit Node（出口节点）**。

今天就来用通俗易懂的语言，带你全面认识 Exit Node 的概念、工作原理、实用场景以及配置要点。

---

## 基本概念：什么是 Exit Node？

简单来说，**Exit Node（出口节点）就是你在 Tailscale 网络中指定的一台“代理网关设备”。开启后，你当前设备的所有公网互联网流量，都会先经过加密隧道打包发送到这台设备，再由这台设备代替你访问公网。**

### 1. 通俗比喻：“专属贴身保镖与安全大门”
为了更形象地理解，我们可以打个比喻：

- **普通 Tailscale 模式（分流）**：就像你在不同城市有几处私人别墅。每当你在别墅之间来往时，走的是非常安全的私人地下密道；但如果你要去当地的菜市场或超市买东西，你依然是推开当前别墅的大门直接走上大街。
- **Exit Node 模式（全局出口）**：相当于无论你想去哪儿（即使是去逛公共网页），你都绝不推开本地陌生街区的大门，而是坐上装甲车，穿过地下密道一路回到你最信任的“大本营”（Exit Node 设备），然后从大本营的大门走出去面向互联网。

### 2. 分流模式 vs 出口节点模式对比

| 对比维度 | 默认模式（Split Tunnel） | 出口节点模式（Exit Node） |
| :--- | :--- | :--- |
| **私有设备通信 (100.x.y.z)** | 走 Tailscale 加密隧道 | 走 Tailscale 加密隧道 |
| **日常公网网页流量** | 直接走本地物理 Wi-Fi / 5G | 全部加密送往 Exit Node 转发 |
| **对外显示的公网 IP** | 当前咖啡厅/酒店 Wi-Fi 的 IP | **Exit Node 所在网络的大网 IP** |
| **适用场景** | 日常文件互传、内网穿透运维 | 公共 Wi-Fi 安全防窃听、归属地 IP 需求 |

> [!NOTE]
> 想要了解在不同系统上开启出口节点的详细命令和参数，可以查阅 [Tailscale 官方文档关于 Exit Nodes 的配置与使用指南](https://tailscale.com/docs)。

## 进一步理解：Exit Node 的工作流程与核心机制

Exit Node 是如何将一台普通设备变成你的专属网络中继站的？它的工作流程主要分为以下三个步骤：

```
[ 你的手机 / 笔记本 ] 
       │ 
       │ (1. 全流量 WireGuard 加密打包: 0.0.0.0/0)
       ▼
[ Tailscale 加密隧道 ]
       │
       ▼
[ Exit Node 出口设备 (家里的 NAS / 软路由 / 云 VPS) ]
       │ 
       │ (2. 解密流量并进行 NAT 转发)
       ▼
[ 目标公网网站 (如 Wikipedia / 各种服务) ]
```

### 1. 声明与开启 IP 转发（服务端）
要让一台设备（例如家里的软路由、Ubuntu 服务器、群晖 NAS 或 Apple TV）充当 Exit Node：
- 操作系统必须开启系统的 IP 转发功能（在 Linux 下即配置 `net.ipv4.ip_forward = 1`）；
- 在 Tailscale 客户端中宣告自己为出口节点（命令行参数为 `tailscale up --advertise-exit-node`）。

### 2. 控制台安全审批（管理员授权）
Tailscale 遵循严格的安全零信任原则。为了防止某台被恶意入侵的设备私自声明出口节点来“劫持”你的全网流量，所有宣告的 Exit Node 必须由管理员在 Tailscale 云端控制台（Admin Console）中**手动点击“Approve（批准）”**后方可生效。

### 3. 客户端一键切换
在你的手机、Mac 或 Windows 电脑上的 Tailscale 客户端里，你会看到一个“Exit Nodes”选项。点击展开列表，选择你刚刚批准的设备，点击“Use Exit Node”即可。

客户端会自动将操作系统的全局默认网关（`0.0.0.0/0` 和 `::/0`）指向 Tailscale 虚拟网卡，整个过程无需断网，数秒内无缝切换。

### 4. 允许局域网访问（Allow Local Network Access）
开启全局出口后，有些用户依然需要连接当前身边的本地无线打印机或投影仪。Tailscale 贴心地提供了“Allow Local Network Access”开关。开启后，访问本地物理局域网（如当前酒店的内网资源）的请求会被保留在本地，其余公网流量依然走 Exit Node。

## 实际应用：Exit Node 的典型使用场景

### 1. 公共场所 Wi-Fi 安全防护（防抓包、防劫持）
在咖啡馆、商场、机场或酒店连接开放式 Wi-Fi 时，你的所有明文流量、DNS 请求都有可能被中间人嗅探或篡改。开启 Exit Node 后，所有从你设备发出的数据包从第一跳开始就是强加密的 WireGuard 密文，公共 Wi-Fi 的所有者只能看到你与家里 Exit Node 之间的加密通信，无法获取你的任何真实浏览内容。

### 2. 借助家庭宽带 IP 访问受限服务
许多地区性的流媒体、网络电视（IPTV）、国内网银系统或公司内部仅限特定宽带 IP 登录的系统，在异地或国外访问时会触发风控拦截。通过将家里常开的 NAS 或软路由设为 Exit Node，你在全球任何地方上网时，对外界而言都等同于“正坐在家里的客厅上网”。

### 3. Apple TV 打造零噪音 24 小时低功耗出口
Tailscale 官方的 Apple TV 客户端支持直接作为 Exit Node 和 [Subnet Router](/blog/tools-19/)。由于 Apple TV 功耗极低（仅几瓦）、发热量小且常年待机通电，非常适合作为家庭网络的常驻出口网关。

### 4. 统一云端出口与运维白名单
开发团队经常需要访问设置了 IP 白名单的生产环境数据库。如果团队成员分布在不同城市，给每个人频繁变更白名单非常危险且繁琐。可以让大家连接同一台云端固定 IP 的 Exit Node，从而以统一的静态 IP 出站。

## 常见误区：使用 Exit Node 的注意事项

### 误区一：“为什么一开启 Exit Node，我的下载速度就变慢了？”
**纠正**：Exit Node 的网络性能严格遵循**“木桶短板理论”**。当你使用 Exit Node 时，流量路径是：`你的手机 -> 家庭 Exit Node -> 目标网站 -> 家庭 Exit Node -> 你的手机`。
- 你的最大下载速度，取决于**家庭宽带的上行速率**（国内普通家庭宽带上行通常只有 30M~50Mbps）。
- 网络延迟等于“你到家里的延迟”加上“家里到目标网站的延迟”。因此，如果 Exit Node 所在网络带宽较小或物理距离过远，速度变慢是正常物理规律。

### 误区二：“把海外 VPS 设为 Exit Node 就能完美替代专业代理工具吗？”
**纠正**：Tailscale 主要是为私密虚拟组网设计的，底层是标准的 WireGuard UDP 流量。在跨境复杂网络环境下，纯粹的 WireGuard 协议没有专门针对审查防火墙的混淆对抗设计，容易遇到 QoS 丢包或未知 UDP 阻断。对于需要高强度混淆代理的场景，专用的代理协议依然不可或缺。

### 误区三：“任何连入 Tailscale 的设备都会自动变成 Exit Node 吗？”
**纠正**：不会。成为 Exit Node 必须显式通过命令行或开关声明，并且必须由管理员在后台审核批准。未授权的普通设备绝对无法成为出口节点。

## 总结

Tailscale Exit Node 是一项极具实用价值的进阶功能。它将原本轻量分流的点对点网状网络，按需扩展为具备全局加密转发能力的“完整网关隧道”，为你出门在外的网络安全与 IP 归属地需求提供了强有力的保障。

除了将单台机器作为全局上网出口，如果你希望无需在家里每个智能家居设备上安装客户端，就能在外直接访问整个家庭内网，该如何实现呢？请继续阅读下一篇文章：[什么是 Tailscale Subnet Router？](/blog/tools-19/)。
