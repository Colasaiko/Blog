虽然绝大多数网站都开启了 HTTPS 加密，但在建立连接之前发起的传统 DNS 查询往往依然是明文传输的，极易被运营商或公共网络监听甚至劫持。**DNS over HTTPS（DoH）** 的做法正是把 DNS 请求封装进标准的 443 端口 HTTPS 流量中，从根本上防止域名窥探与解析篡改。

然而，鲜为人知的是：**在过去几十年中，你在访问这个加密网站之前所发出的 DNS 查询，几乎全都是“裸奔”的。**

当你向传统 DNS 服务器询问“请问 `google.com` 在哪”时，这个请求是通过明文发送的。任何监听你所在公共 Wi-Fi、宽带路由器或沿途网络节点的第三方，都能轻而易举地看到你正在尝试访问哪个网站，甚至能伪造一个假 IP 把你引向钓鱼网站（即 DNS 劫持 / 污染）。

为了彻底堵住这个历史遗留的隐私大漏洞，**DNS over HTTPS（简称 DoH）** 应运而生。

今天就来用通俗的语言，为你全面剖析什么是 DoH、它是如何保护你的网络隐私的，以及如何在各种设备上轻松开启它。

## 基本概念：什么是 DNS over HTTPS (DoH)？

### 1. DoH 的定义与核心原理
**DNS over HTTPS（DoH，RFC 8484 标准）** 是一种用于执行加密 DNS 解析的安全网络协议。

它的核心思想非常朴素而巧妙：**把传统的 DNS 查询数据包，打包塞进标准的 HTTPS 加密通道（443 端口）中进行传输。**

在传统模式与 DoH 模式下，网络请求的传输方式有着天壤之别：

```
【传统明文 DNS】
你的设备 ───[ 明文明信片: "我想去 example.com" (UDP 53) ]───► 运营商/DNS服务器
             ▲ 中途任何人（公共 Wi-Fi、黑客、审查设备）都能一眼看清内容，甚至篡改

【DNS over HTTPS (DoH)】
你的设备 ───[ 加密防弹包裹 (HTTPS/TLS 443) 内部封装 DNS 查询 ]───► DoH 服务器 (如 Cloudflare)
             ▲ 沿途只能看到你在传输普通的 HTTPS 流量，无法窥视具体的域名与内容
```

- **传统 DNS 的比喻**：就像你寄送一张**透明明信片**。邮递员和沿途任何经手的人，都能看清你写在上面的收件人网址。
- **DoH 的比喻**：你把明信片装进了一个**防窥防弹的特快专递信封（HTTPS 加密）**，并且混入成千上万个普通的快递包裹（443 网页流量）中一同寄出。外人既无法看穿信封内部写了什么，也无法辨别这是一个普通的网页浏览还是一个 DNS 查询。

关于 DoH 的官方支持与背景规范，可以参考 [Mozilla Firefox 官方 DoH 知识库](https://support.mozilla.org/en-US/kb/dns-over-https) 以及 [Cloudflare DNS 技术文档](https://developers.cloudflare.com/dns/)。

## 进一步理解：DoH 带来了哪些核心优势？

为什么主流浏览器（如 Chrome、Firefox、Edge）和各大操作系统都在极力推广 DoH？这源于它带来的三大核心安全保障：

### 1. 防窃听：终结“浏览轨迹裸奔”
在传统的网络环境下，即使你使用了隐私无痕模式，你的宽带运营商（ISP）或公共场所的 Wi-Fi 管理员，依然可以通过监控 53 端口的明文 DNS 流量，记录下你访问过的每一个域名清单。
DoH 通过现代 TLS 加密技术，使 DNS 查询内容对中间人完全隐形，从源头上保护了你的上网行踪隐私。

### 2. 防篡改与防劫持：确保答案真实可信
在明文 DNS 时代，恶意的网络节点可以抢在正规 DNS 服务器之前，向你的设备返回一个伪造的 IP 地址（例如将你引导至假冒的银行登录页或满是垃圾弹窗的广告页）。
DoH 借助数字证书验证体系，严格确认服务端身份，保证返回的解析结果 100% 来自你指定的受信任服务器，中间人无法插手篡改。

### 3. 防阻断与高兼容性：隐身于标准 443 端口
这是 DoH 相比其他加密方案（如 DoT）的一大杀手锏。
DoH 使用的是与所有普通 HTTPS 网站完全相同的 **443 端口**。对于任何网络防火墙或网关来说，它看起来与普通的网页浏览数据流完全一致。中间设备如果想要强行阻断 DoH，就不得不切断整个 443 端口的正常网络访问，这在绝大多数网络环境中是不可行的。

## 实际应用：主流设备与软件如何开启 DoH？

配置 DoH 非常简单，现代主流浏览器和操作系统多数已内置原生支持。

### 1. 常见的主流公共 DoH 服务地址
在配置 DoH 时，你需要填入服务商提供的 DoH 查询 URL（Endpoint）：

| 提供商 | DoH 查询地址 (Endpoint URL) | 节点优势与特点 |
| :--- | :--- | :--- |
| **Cloudflare** | `https://cloudflare-dns.com/dns-query` | 全球顶级 CDN 覆盖，严格零日志隐私策略 |
| **Google** | `https://dns.google/dns-query` | 全球解析高可用，庞大骨干网支撑 |
| **阿里 DNS (AliDNS)** | `https://dns.alidns.com/dns-query` | 中国大陆地区极速响应，国内 CDN 精准调度 |
| **腾讯 DNSPod** | `https://doh.pub/dns-query` | 腾讯云骨干支持，防运营商劫持表现优异 |
| **Quad9** | `https://dns.quad9.net/dns-query` | 瑞士非营利机构，内置恶意软件与钓鱼域名拦截 |

### 2. 在浏览器中一键开启 DoH
- **Google Chrome / Microsoft Edge**：
  1. 打开浏览器设置 $\rightarrow$ 进入「隐私和安全」 $\rightarrow$ 点击「安全」。
  2. 找到「使用安全 DNS（Use secure DNS）」。
  3. 选择「自定义」，并填入你喜欢的 DoH 链接（例如 Cloudflare 或阿里 DNS）。
- **Mozilla Firefox**：
  1. 打开「设置」 $\rightarrow$ 搜索「DNS」。
  2. 在「启用基于 HTTPS 的 DNS」中，选择「增强保护」或「最高保护」，并选择提供商。

### 3. 在网络分流与代理工具中的应用
在 Clash、Clash Verge 或 sing-box 等进阶网络客户端中，DoH 是防范 DNS 污染与 DNS 泄漏的核心利器：
- 可以在客户端配置文件中的 `dns` 模块，将 `nameserver` 或 `default-nameserver` 指定为 DoH 链接（如 `https://1.1.1.1/dns-query` 或 `https://223.5.5.5/dns-query`）。
- 结合客户端的分流规则，实现境内域名走国内 DoH、境外域名走海外代理端安全解析的完美分工。

## 常见误区：彻底理清对 DoH 的误解

### 误区一：“开启了 DoH，就等于开启了全局代理/VPN，可以无限制访问所有网站？”
**纠正**：**完全不是！**
这是新手最容易产生的巨大误解。
DoH **仅仅保护了域名解析这一步**。当你通过 DoH 成功获取到了网站的真实 IP 后，你的电脑后续依然需要与该 IP 建立实际的 TCP/HTTPS 数据连接。在建立连接时：
1. 目标 IP 地址依然是公开可见的；
2. HTTPS 握手中的 **SNI（Server Name Indication，服务器名称指示）** 扩展在大多数情况下依然会暴露你访问的域名。
如果目标网站的 IP 或 SNI 被防火墙阻断，单靠 DoH 依然无法直接打开网页。

### 误区二：“DoH 因为多了加密解密过程，上网速度一定会变慢很多？”
**纠正**：**日常感知几乎没有差别，甚至可能更快**。
虽然 TLS 加密握手需要额外的计算，但现代 DoH 普遍基于 **HTTP/2 和 HTTP/3 (QUIC)** 协议构建，支持**连接复用（Connection Reuse）**与零往返延迟（0-RTT）恢复。一旦初次建立连接，后续的 DNS 查询都可以复用现有通道瞬间完成，配合本地 DNS 缓存，几乎感受不到任何延迟增加。

### 误区三：“使用了 DoH，我的上网数据就百分之百无人知晓了？”
**纠正**：**这取决于你对 DoH 服务商的信任度**。
中间的黑客和运营商确实看不见你的请求了，但**你所选择的 DoH 服务商依然能清楚看到你查了哪些域名**。因此，务必选择有严格隐私审计背书的知名公共服务商（如 Cloudflare、Google、Quad9 等），切勿随意连接来历不明的私人 DoH 节点。

## 总结

DNS over HTTPS (DoH) 是互联网安全演进历程中的一座重要里程碑。它将原本脆弱、裸露的传统 DNS 查询装进了坚固的 HTTPS 加密信封中，有效解决了中间人窃听、域名劫持和恶意篡改的顽疾。

除了 DoH 之外，网络安全标准组织还制定了另一个同样强大的加密 DNS 方案——**DNS over TLS (DoT)**。
