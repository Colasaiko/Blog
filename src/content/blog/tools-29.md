在安卓系统的「私人 DNS」设置或软路由配置中，你经常会看到基于 TLS 加密的 DNS 选项。这就是与 DoH 并驾齐驱的另一大加密解析标准——**DNS over TLS（DoT）**。它直接通过专用的 853 端口建立 TLS 隧道，在没有额外 HTTP 协议开销的前提下保障解析隐私。

不过，如果你经常使用 Android（安卓）手机，你可能在系统的网络设置中看到过一个名为**“私人 DNS（Private DNS）”**的选项；或者在配置软路由与 Linux 服务器时，频繁接触到 `tls://` 开头的 DNS 地址。

这里的“私人 DNS”在底层所采用的核心技术，正是与 DoH 并驾齐驱的另一大国际加密标准——**DNS over TLS（简称 DoT）**。

DoT 究竟是什么？它与 DoH 有何区别？在日常使用中我们又该如何选择？今天就来为你进行全方位的详细解读。

---

## 基本概念：什么是 DNS over TLS (DoT)？

### 1. DoT 的核心定义
**DNS over TLS（DoT，RFC 7858 标准）** 是一种通过 **TLS（传输层安全性协议）** 对传统 DNS 查询与响应进行端到端加密的安全通信协议。

如果说传统的明文 DNS 是直接在无保护的 UDP 53 端口上大声喊话，那么 DoT 的做法是：**在设备与 DNS 服务器之间建立一条专用的加密安全隧道（默认使用标准的 853 端口），所有的域名查询都在这条隧道内部受保护地传输。**

```
【传统明文 DNS】
设备 ───[ 明文 UDP 53 端口 ]───► DNS 服务器 (无加密，易被截获)

【DNS over TLS (DoT)】
设备 ───[ 专属加密 TLS 隧道 (TCP 853 端口) ]───► DNS 服务器 (纯粹加密，无 HTTP 开销)

【DNS over HTTPS (DoH)】
设备 ───[ HTTPS 网页包装 (TCP 443 端口) ]───► DNS 服务器 (混入普通网页流量)
```

### 2. 生动形象的生活比喻
为了更好地理清三者的区别，我们可以打个比喻：
- **传统 DNS**：你在嘈杂的公共大厅里扯着嗓子大声向柜台工作人员询问某个人的住址，大厅里的所有人都能听得清清楚楚。
- **DoT（专属保密通道）**：银行为了保护客户隐私，特意在大厅旁边开辟了一条**专用的单人 VIP 保密通道（853 端口）**。你走进专属通道内与工作人员一对一交谈，外人绝对听不到谈话内容，但外人能知道你走进了这个“保密通道”。
- **DoH（伪装快递信封）**：你把写有询问纸条的信件塞进了**标准的普通快递盒中（443 端口）**，混在每天进出大楼的成千上万个普通快递中一同运送，外人既不知道盒子里写了什么，也分不清这是普通快递还是询问信件。

关于 DoT 的权威定义与安全规范，可以参考 [Cloudflare DNS 技术文档](https://developers.cloudflare.com/dns/)。

## 进一步理解：DoT 与 DoH 的全方位对比

既然 DoT 和 DoH 都能完美实现对 DNS 请求的加密，为什么还需要存在两种不同的标准？它们在协议设计和应用场景上有哪些关键差异？

我们可以通过以下全景对比表来清晰认知：

| 对比维度 | DNS over TLS (DoT) | DNS over HTTPS (DoH) | 传统 DNS |
| :--- | :--- | :--- | :--- |
| **IETF 标准规范** | RFC 7858 | RFC 8484 | RFC 1035 |
| **标准网络端口** | **专用 853 端口** | **通用 443 端口**（与 HTTPS 共享） | **53 端口** |
| **底层协议栈** | `DNS -> TLS -> TCP` | `DNS -> HTTP/2 -> TLS -> TCP` | `DNS -> UDP/TCP` |
| **协议额外开销** | **极低**（无 HTTP 头部包装） | 稍高（包含 HTTP 协议层封装） | 最低（明文） |
| **网络可识别性** | **特征明显**（专用端口，易于识别与管控） | **极难分辨**（完全伪装为普通 Web 流量） | 明文裸奔 |
| **网络管理与阻断** | 企业/学校网管可轻松在防火墙封禁 853 端口 | 无法单独封禁 443 端口，否则普通网站瘫痪 | 极易被劫持/篡改 |
| **操作系统原生支持** | **Android 原生内置**（Android 9+ 私人 DNS） | Windows 11、macOS、iOS 原生支持良好 | 所有系统全平台支持 |
| **应用层集成** | 多用于操作系统底层、网关与路由器 | 多用于浏览器（Chrome/Firefox）与代理客户端 | 默认基础方案 |

### 1. 协议精简性：DoT 更纯粹高效
从协议架构上看，DoT 是直接在原生的 DNS 报文外层裹上了一层 TLS 加密套件，架构纯粹、直截了当。而 DoH 则是在 DNS 报文外面先包裹了一层 HTTP 协议请求头，然后再进行 TLS 加密。
因此，在对系统资源敏感、计算性能有限的嵌入式硬件（如家用路由器、低功耗软路由）上，DoT 往往具有更轻量、更高效的运行表现。

### 2. 穿透与抗审查能力：DoH 更胜一筹
由于 DoT 使用的是专属的 **853 端口**，在某些网络环境（例如公司内网、学校机房或公共热点）下，网络管理员出于合规或安全监控考量，可以轻而易举地在企业防火墙上封闭 853 端口，导致 DoT 彻底无法连通。
相比之下，DoH 隐蔽在无可替代的 **443 端口**中，天然具备极强的抗阻断能力与穿透性。

## 实际应用：在日常设备中如何使用 DoT？

DoT 在移动操作系统、智能路由器与网络代理软件中有着极其广泛的原生支持。

### 1. Android 系统的“私人 DNS”配置指南
从 Android 9（Pie）开始，安卓系统原生集成了 DoT 支持，无需下载任何第三方 App：

1. 打开手机「系统设置」 $\rightarrow$ 进入「网络和互联网」或「更多连接方式」。
2. 找到「私人 DNS（Private DNS）」选项。
3. 选择「私人 DNS 提供商主机名（Private DNS provider hostname）」。
4. 填入主流服务商提供的 DoT 主机名即可：

| 提供商 | Android 私人 DNS 填写的主机名 | 适用场景与优势 |
| :--- | :--- | :--- |
| **阿里 DNS (AliDNS)** | `dns.alidns.com` | 中国大陆首选，极速国内解析调度 |
| **腾讯 DNSPod** | `dot.pub` | 国内稳定低延迟，抗劫持性能出色 |
| **Cloudflare** | `1dot1dot1dot1.cloudflare-dns.com` | 全球优质线路，严格隐私保护 |
| **Google** | `dns.google` | 全球解析高可用，生态兼容性好 |
| **AdGuard DNS** | `dns.adguard-dns.com` | 具备系统级广告过滤与恶意域名拦截功能 |

配置完成后，手机上所有应用程序（无论是浏览器、游戏还是社交软件）发出的 DNS 请求都会被安卓系统自动重定向至该加密通道中，无需逐个 App 分别配置。

### 2. 在路由器与本地 DNS 转发器中的应用
在 OpenWrt、AdGuard Home、SmartDNS、pfSense 等路由器固件和网络管理套件中，DoT 常被广泛配置为上游 DNS（Upstream DNS）：
- 例如在 AdGuard Home 的上游 DNS 中直接填入：`tls://dns.alidns.com` 或 `tls://1.1.1.1`。
- 路由器本地维护一个高性能的缓存池，对外解析全部通过 DoT 加密隧道向公网发出，从而让接入家庭局域网的所有设备（包括智能电视、IoT 智能家居）被动享受到加密 DNS 的保护。

## 常见误区：关于 DoT 的典型认知盲区

### 误区一：“DoT 用的 TLS 加密强度不如 DoH 的 HTTPS？”
**纠正**：**两者的底层加密强度完全一致**。
DoT 和 DoH 使用的都是现代主流的 **TLS 1.3** 加密协议和相同的对称加密算法（如 AES-GCM 或 ChaCha20-Poly1305）。无论是抵抗窃听、防止中间人篡改还是证书鉴权，两者的安全性在密码学层面上没有高低之分。

### 误区二：“在公司电脑配置了 DoT 就能偷偷浏览受限制网站而不被发现？”
**纠正**：**不能**。
首先，公司网管很容易直接在网关上切断 853 端口的访问，导致你的 DoT 解析直接断网。其次，即使解析成功，当你访问网站时，随后的明文 SNI 握手和目标服务器 IP 依然会在公司网关的流量监控系统中一览无余。

### 误区三：“DoT 和 DoH 哪个更好？我应该彻底放弃其中一个吗？”
**纠正**：**两者是互补关系，各展所长**：
- 在**安卓手机系统全局设置**、**家用软路由/AdGuard Home 网关**中，推荐优先使用纯粹高效的 **DoT**；
- 在**桌面浏览器（Chrome/Firefox）**、**公司严格网络环境**以及**代理客户端的分流策略**中，推荐使用抗干扰能力更强的 **DoH**。

## 总结

DNS over TLS (DoT) 以其专用的 853 端口和轻量、纯粹的 TLS 加密隧道架构，成为了现代操作系统与网关设备实现系统级 DNS 加密的标准方案。与 DoH 一同构成了抵御网络监听、消除明文 DNS 劫持的双重防线。

在日常上网过程中，无论是使用传统 DNS、DoH 还是 DoT，我们总会遇到偶尔网页打不开、加载无限转圈的棘手状况。此时，我们该如何科学排查？如何准确判断这到底是不是 DNS 引起的故障？
