如果所有流量都不加区分地走代理，国内网站容易变慢且频触风控；如果全部直连，海外资源又无法访问。想要实现「国内直连、海外加速、广告拦截」，核心就在于 sing-box 的 `route` 模块及其分流规则体系。

想象一下：如果你在上网时，所有的数据流量都不加区分地全部走代理服务器，那么你打开国内的购物、外卖、视频网站时不仅速度变慢、浪费代理流量，还可能因为异地 IP 登录频繁触发安全验证；反之，如果所有流量都直连，那些需要加速的海外学术资源、社交平台又无法打开。

要做到“访问国内网站走本地高速直连，访问海外服务走优质代理，遇到垃圾广告自动拦截”，靠的就是 sing-box 中的核心利器——**分流规则（Routing Rules）**。

今天就来为你通俗透彻地讲解 sing-box 中的规则体系：规则是如何定义的、它是如何判断流量去向的，以及如何利用规则打造丝滑的网络体验。

## 基本概念

什么是 sing-box 中的规则？

简单来说，**规则是一组“条件与动作”的判断逻辑**。当你的设备发起任何一个网络连接时，sing-box 都会检查这个连接的特征，一旦符合预设条件，就执行对应的出站动作。

它的基本判断逻辑是：
> **如果（IF）** 满足某些特征（例如：目标网址是 `baidu.com`，或者目标 IP 属于中国大陆）  
> **那么（THEN）** 执行指定出站（例如：走 `direct` 直连通道）

### “智能快递分拣中心”的比喻

我们可以把 sing-box 的规则系统想象成一个**自动化的快递分拣流水线**：

- 每当你的手机或电脑发送一个数据包，就相当于寄出一个“快递包裹”；
- 包裹上贴着面单，上面写着收件人域名、目标 [IP 地址](/blog/guide-02/)、通信端口以及发送该包裹的软件程序名；
- 分拣流水线上装有多个光学扫描仪（规则检查器）；
- **扫描仪 1** 发现包裹是恶意的广告域名，立即将其推入碎纸机（`block` 拦截）；
- **扫描仪 2** 发现收件地址是国内电商网站，将其送往国内陆运直连卡车（`direct` 直连）；
- **扫描仪 3** 发现收件地址是特定海外流媒体，将其送往专用的跨国航空专线（`proxy` 代理）；
- 如果所有扫描仪都没认出这个包裹，就按照默认章程处理（`final` 出站）。

这就是规则在后台默默执行的自动化调度过程。想了解官方支持的所有规则字段定义，可以查阅 [sing-box 官方文档](https://sing-box.sagernet.org/)。

## 进一步理解：规则的核心机制与匹配维度

要掌握 sing-box 的规则，需要理解它的四大匹配维度以及关键的运行机制：

### 1. 多维度的匹配条件

sing-box 提供了极其丰富且细致的规则匹配条件：

1. **域名匹配（Domain）**：
   - `domain`：完全精确匹配（如 `google.com` 只匹配该主域名）；
   - `domain_suffix`：域名后缀匹配（如 `.google.com` 可以匹配 `maps.google.com`、`mail.google.com` 等所有子域名）；
   - `domain_keyword`：域名关键字匹配（只要域名包含某个词即命中）；
   - `domain_regex`：正则表达式高级匹配。
2. **IP 地址与地理位置（IP & GeoIP）**：
   - `ip_cidr`：具体的 IP 网段匹配（如局域网 `192.168.0.0/16`）；
   - `ip_is_private`：自动识别局域网私有 IP 并直连；
   - `geoip`：国家与地区 IP 库匹配（如 `geoip:cn` 表示所有中国大陆 IP）。
3. **协议与端口（Protocol & Port）**：
   - `port` / `port_range`：指定目标端口（如网页的 `80`、`443`，邮件的 `25` 等）；
   - `network`：匹配传输层协议（`tcp` 或 `udp`）；
   - `protocol`：利用流量嗅探（Sniffing）识别应用层协议（如 `http`、`tls`、`dns`、`bittorrent` 等）。
4. **应用程序与进程（Process & App）**：
   - `process_name`：电脑端根据发起连接的程序名进行匹配（如 `chrome.exe`、`telegram.exe`）；
   - `package_name`：Android 手机端根据 App 包名分流。

### 2. “自上而下，首次命中”原则

sing-box 评估规则时遵循严格的**先后顺序原则（First Match Win）**：

- 数据包进入路由模块后，会从规则列表的第一条自上而下依次比对；
- **一旦某一条规则匹配成功，sing-box 就会立刻执行该规则指定的出站，并终止后续所有规则的检查**；
- 如果从头到尾没有匹配到任何一条规则，流量最后会落入 `final`（最终兜底出站）。

**关键启示**：规则的摆放顺序至关重要。越特殊、越优先的规则（如广告拦截、特定应用的专线直连）必须放在最上方；越宽泛、通用的规则必须放在下方。

### 3. 革命性的 Rule-Set（规则集 / SRS 机制）

在早期的代理工具中，几万条国内域名和 IP 规则直接以长文本写在配置文件里，不仅文件庞大臃肿，还会占用大量设备内存。

sing-box 引入了**规则集（Rule-Set）**：
- **SRS 二进制规则集**：将海量的域名和 IP 规则预先编译为二进制文件（`.srs`），体积压缩到极小，匹配速度极快，内存占用几乎可以忽略；
- **自动远程更新**：你只需在配置中引用规则集的远程下载链接，客户端会在后台定期自动更新，无需手动维护冗长的域名列表。

## 实际应用

一套成熟、优雅的 sing-box 规则配置通常是如何组织的？我们来看一个最经典的日常分流配置结构：

### 1. 广告拦截层（最顶层，优先丢弃）
```json
{
  "rule_set": "geosite-category-ads-all",
  "outbound": "block"
}
```
*作用*：识别出所有已知的广告、追踪和恶意营销域名，直接丢弃，提升网页加载速度并保护隐私。

### 2. 本地与局域网直连层（第二层，保障内网互通）
```json
{
  "ip_is_private": true,
  "outbound": "direct"
}
```
*作用*：访问路由器后台、局域网 NAS、本地打印机等私有 IP 时，极少不走代理。

### 3. 国内服务直连层（第三层，保障日常高速）
```json
{
  "rule_set": ["geosite-cn", "geoip-cn"],
  "outbound": "direct"
}
```
*作用*：所有国内主流网站、App 和大陆 IP 均直接走本地[网络线路](/blog/guide-01/)，保证外卖、支付、国内视频不卡顿。

### 4. 专属业务定向分流层（第四层，按需指派）
```json
{
  "rule_set": "geosite-openai",
  "outbound": "US-Node"
}
```
*作用*：将对 IP 地区要求苛刻的特定 AI 或海外流媒体服务，精准导流至支持该服务的专属节点。

### 5. 兜底全局层（最底层，处理其余未分类流量）
```json
{
  "final": "Proxy-Selector"
}
```
*作用*：所有未在上述规则中命中的未知外部流量，默认全部交给通用代理策略组处理。

## 常见误区

### 误区一：规则越多越好，把网上所有规则集全部加上
**纠正**：规则集并非越多越好。加载过多重叠、冲突或年久失修的规则集，不仅会增加匹配耗时，还可能导致“直连网站被误判走代理”或“代理服务被误判直连”。保持精简、常用的核心规则集（如 `geosite-cn` + `geoip-cn` + 基础广告集）往往是最稳定的。

### 误区二：规则顺序随意颠倒
**纠正**：如前所述，规则是自上而下匹配的。如果你不小心把 `geoip-cn -> direct` 或者 `final -> proxy` 的逻辑放在了广告拦截规则上方，广告拦截规则就可能永远无法被触发执行。

### 误区三：规则写对了但分流没起作用，一定是节点坏了
**纠正**：分流失效往往与 **DNS 解析** 和 **流量嗅探（Sniffing）** 有关。如果数据在进入规则判断前，域名被本地运营商 DNS 污染成了错误的 IP，或者客户端没有开启域名嗅探导致内核只能看到生硬的 IP 地址，基于域名的规则就可能无法命中。

## 总结

规则是让 sing-box 拥有“智慧”的灵魂所在。

- 通过**条件与动作**的简单映射，它实现了流量的自动化分流；
- 遵循**自上而下、首次命中**的逻辑，它保证了判断的高效与精确；
- 依托现代化的 **SRS 规则集**，它在大幅降低资源消耗的同时保持了对海量域名的毫秒级匹配。
