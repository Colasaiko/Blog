在 Clash 界面中节点测速显示几十毫秒绿字、系统代理开关也已开启，但用浏览器访问 Google 或 GitHub 时却依然提示「无法访问此网站」或 `ERR_CONNECTION_TIMED_OUT`。这种「看似连通、实际断网」的假死现象，多半是由系统代理未正确接管、DNS 污染泄漏、分流规则配置错误或浏览器第三方代理插件冲突造成的。

这种情况就像你坐进了一辆跑车，钥匙插上了，仪表盘亮了，引擎也轰鸣启动了（显示连接成功），但当你踩下油门时车子却一动不动——可能是手刹没放（系统代理未接管）、导航设错了反方向（分流规则错误），或者是前方的跨海大桥实际已经塌方（节点落地机故障）。

为什么会出现“看似连上、实则断网”的假象？今天就来拆解网络请求全流程，帮你透彻理解问题根源，并提供一套立竿见影的排查指南。

## 基本概念

要搞清楚网页为什么打不开，我们需要先理解当你在浏览器输入一个网址（如 `google.com`）并按下回车时，数据到底经历了哪些环节。

```
[浏览器发起请求]
       │
       ▼
[操作系统网络栈] ── (1) 系统代理 (System Proxy) 是否接管流量？
       │
       ▼
[Clash 本地核心] ── (2) DNS 解析是否成功？(Fake-IP / Direct)
       │
       ▼
[分流规则引擎]   ── (3) 匹配规则是 PROXY、DIRECT 还是 REJECT？
       │
       ▼
[中转/入口节点]  ── (4) TCP 握手成功 (产生测速延迟数值)
       │
       ▼
[境外落地节点]   ── (5) 落地机转发至目标网站 (真实互联网出口)
       │
       ▼
[目标网站返回]
```

### 什么是 Clash 界面上的“连接成功”？
在 Clash 客户端中，所谓的“连接成功”或“节点显示绿色延迟”，通常仅仅代表**第 (4) 步**正常：
- **核心启动成功**：Clash 的后台核心进程（Clash Core 或 Mihomo/Meta Core）正常驻留内存，并在本地开启了监听端口（默认通常是 `7890`）。
- **节点握手成功**：客户端向节点的入口服务器发送了一次轻量的 HTTP/TCP 探测包，并在几十毫秒内收到了回应。

但这**绝不等于**你的浏览器流量已经顺利通过节点访问到了目标网站。只要上述 5 个环节中有任何一环断裂，浏览器就会报出网页无法打开的错误。

## 进一步理解：连上了却打不开网页的 5 大根本原因

### 1. 系统代理（System Proxy）未生效或被覆盖
这是导致新手“打不开网页”最常见的原因。
- **开关虽开，系统未改**：Clash 软件界面上的“System Proxy”开关虽然点亮了，但由于 Windows 注册表权限受限、杀毒软件拦截或 UAC 限制，操作系统底层的代理设置并没有真正被修改为 `127.0.0.1:7890`。
- **浏览器插件冲突**：如果你的 Chrome 或 Edge 浏览器安装了 SwitchyOmega、油猴脚本或其他代理类扩展，浏览器会优先使用插件的代理设置，直接绕过了 Clash 的系统代理。

### 2. 路由分流模式与策略组配置错误
Clash 拥有强大的分流能力，但也容易因为模式选择错误导致断网：
- **误切为 Direct（直连模式）**：在直连模式下，所有国外流量都不走代理，而是直接由你的本地宽带访问，自然打不开被墙网站。
- **规则组（Rule）指定到了无效节点**：在规则模式下，`PROXY` 或 `GLOBAL` 策略组可能被误设为一个已经失效、超时或流量用尽的节点组。
- **规则漏匹配**：访问某些小众或新域名时，规则库中没有收录该域名，默认被回退规则（FINAL / MATCH）丢给了 `DIRECT` 直连。

### 3. DNS 污染与死锁解析故障
访问网页的第一步是域名解析（把 `google.com` 变成 IP 地址）。Clash 采用独特的 DNS 机制（如 Fake-IP 或 Redir-Host）：
- **DNS 死锁**：如果本地网络环境不稳定，或者 Clash 配置的远程上游 DNS 服务器（如 `8.8.8.8` 或 `1.1.1.1`）无法连通，Clash 就无法完成域名的 DNS 映射。浏览器拿不到 IP 地址，就会报 `DNS_PROBE_FINISHED_NXDOMAIN` 或解析超时。
- **本地 DNS 缓存污染**：在开启 Clash 之前浏览器已经尝试解析并缓存了错误的污染 IP，导致开启代理后依然沿用旧的失效 IP。

### 4. 节点“假活”：仅入口通畅，落地机断网
现在的优质机场普遍采用“国内入口 -> 专线/中转 -> 境外出口（落地机）”的架构：
- **测速测的是入口**：当你在 Clash 界面点击测速时，部分测速机制只测到了国内中转服务器（比如深圳机房，延迟极低只有 15ms）。
- **出口实际已挂**：境外落地服务器（香港、日本、美国机房）可能被墙拦截、机房断网或节点 IP 被目标网站（如 Cloudflare、Google）拉黑。此时虽然测速有数字，但实际上根本无法传输任何出海数据。

### 5. 系统时间不同步导致 SSL 证书握手被拒
现代互联网 99% 的网站都是 `https://` 加密协议。HTTPS 连接在建立时，浏览器与服务器会校验证书的时间有效性。
- 如果你的电脑时间比标准北京时间快或慢了 2 分钟以上，系统在校验证书时就会认定证书无效或过期，直接切断连接并提示 `NET::ERR_CERT_DATE_INVALID` 或“您的连接不是私密连接”。

## 实际应用：排查与修复六步法

遇到网页打不开时，请按照以下顺序逐步排查修复：

```
步骤 1: 检查系统代理与端口监听
   │
步骤 2: 切换到 Global 全局模式测试
   │
步骤 3: 同步系统时钟与时间
   │
步骤 4: 切换多个不同国家节点测试
   │
步骤 5: 开启 TUN 虚拟网卡模式
   │
步骤 6: 清理 DNS 缓存与排查扩展
```

### 步骤一：检查系统代理与本地监听端口
1. 打开 Windows 设置 -> “网络和 Internet” -> “代理”。
2. 查看“手动设置代理”是否处于开启状态，地址是否为 `127.0.0.1`，端口是否为 `7890`（或与你 Clash 设置中的端口一致）。
3. 如果未开启，请在 Clash 界面重新关闭并开启一次“System Proxy / 系统代理”开关；若频繁失效，可尝试以管理员身份运行 Clash。

### 步骤二：切换到 Global（全局模式）进行对照测试
1. 在 Clash 策略组中，将模式从 **Rule（规则）** 切换为 **Global（全局）**。
2. 在 Global 列表中手动选择一个延迟正常的节点（例如香港或日本）。
3. 刷新浏览器访问 `google.com`：
   - **如果全局模式下能打开**：说明节点完全正常，问题出在**分流规则**或 **Rule 模式下的策略组选择**。检查 Rule 模式下对应的代理组是否选错了节点。
   - **如果全局模式下依然打不开**：说明是系统代理未接管、系统时间错误、或者该节点属于“假活”节点。

### 步骤三：同步电脑系统时间
1. 鼠标右键点击电脑任务栏右下角的时间，选择“调整日期和时间”。
2. 确保“自动设置时间”和“自动设置时区”处于开启状态。
3. 点击“立即同步”按钮，确保同步状态显示为对勾绿标。

### 步骤四：更换不同地区和协议的节点
1. 不要只盯着一个显示 20ms 的香港节点，尝试切换到台湾、日本、新加坡或美国节点。
2. 尝试切换不同协议节点（如 Trojan、Vless 或 Shadowsocks），排除个别协议端口遭到运营商本地 QoS 干扰或落地机故障。

### 步骤五：开启 TUN 模式（虚拟网卡接管）
某些应用（如 Windows UWP 应用、部分游戏客户端、甚至某些特殊配置的浏览器）会主动绕过系统代理设置：
1. 在 Clash Verge 或 Clash Meta 中，找到 **TUN Mode（TUN 模式）**。
2. 点击安装虚拟网卡服务（Service Mode / TUN Driver），并开启 TUN 模式开关。
3. TUN 模式会在网络底层虚拟一张网卡，强制接管所有进出流量，有效解决系统代理失效或被绕过的问题。

### 步骤六：清理 DNS 缓存与禁用冲突插件
1. 打开 CMD 命令行窗口，输入 `ipconfig /flushdns` 并回车，清理 Windows 本地 DNS 缓存。
2. 打开浏览器的无痕/隐私窗口（Incognito Window），无痕模式默认会禁用所有浏览器插件。在无痕窗口中测试网页能否打开，若能打开，则逐一排查并禁用有冲突的浏览器代理扩展。

## 常见误区

| 常见误区 | 正确认知 |
| :--- | :--- |
| **误区一：只要节点测速显示绿色延迟，就一定能连接国际网络** | 测速往往只测到了中转入口的连通性，出口机房断网或被墙依然会导致网页打不开。 |
| **误区二：国内网站打得开，说明代理没问题** | 国内网站默认走 Direct 直连，完全不经过代理服务器；国内网站通畅只能说明本地宽带没断，不能证明代理工作正常。 |
| **误区三：遇到打不开就卸载重装浏览器** | 核心问题在代理链路、DNS 与路由策略，重装浏览器极少能解决这类网络配置问题。 |
| **误区四：TUN 模式和系统代理必须同时开或者都不能关** | 普通浏览网页只需开启系统代理；遇到 UWP 软件或代理失效时开启 TUN 模式即可，无需过度复杂化设置。 |

## 总结

“Clash 显示连接成功但网页打不开”是一个典型的链路分段故障。解决这个问题的核心逻辑在于**分段隔离排查**：

1. **入口排查**：确认系统代理是否真正下发给操作系统（或使用 TUN 模式全面接管）；
2. **模式隔离**：用 Global 全局模式排除分流规则配置错误；
3. **出口验证**：多切几个不同地区的节点，排除单一落地节点假活或出口故障；
4. **底层校准**：同步系统时间与清理 DNS 缓存，排除证书与域名解析拦截。

掌握了这一套排查逻辑，以后无论遇到何种网络连通异常，你都能在两分钟内精准定位并恢复网络通畅。
