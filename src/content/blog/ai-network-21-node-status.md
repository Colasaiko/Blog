在使用各种网络代理客户端访问 ChatGPT、Claude 等 AI 网站时，我们经常会在软件界面上看到节点的各种状态：有的显示“在线”，有的显示“离线”，或者标注了具体的延迟数字（如 150ms）。

但是，很多新手朋友会遇到一个疑惑：**为什么节点明明显示“在线”，却依然打不开网页？** 今天就来带你深入了解在线节点和离线节点的真正区别，以及如何准确判断节点的连通性。

## 在线与离线的基础定义

在网络客户端的界面中，节点状态通常是通过简单的网络测速机制来判断的。

- **在线节点**：客户端通过发送简单的数据包（例如 Ping 或 TCP 握手请求）到节点服务器，并在规定时间内收到了响应。此时客户端会认为节点是“活着的”，标记为在线。
- **离线节点**：客户端发送了请求，但在超时时间内（通常为数秒）没有收到任何回应，客户端就会将该节点标记为离线、Timeout 或超时。

## 为什么显示在线却无法上网？

这就是许多用户最常遇到的“假在线”现象。要理解这个问题，我们需要区分两种常见的测速方式：**Ping 测试 (TCP Ping)** 和 **HTTP 延迟测试 (真连接测试)**。

### 1. TCP Ping 的局限性

多数客户端默认的测速方式是 TCP Ping。它只测试你的设备到“代理服务器”这一段的连通性。
如果节点服务器在运行，并且网络畅通，TCP Ping 就会成功并返回一个延迟数字（如 50ms）。这代表**你可以连上这个节点服务器**。
但是，这**不代表**这个节点服务器本身能够正常访问外网（国际互联网）。如果节点的出口 IP 被封锁、或者服务端配置错误，它依然无法为你转发流量。这就是为什么显示“在线”但依然上不了网。

### 2. HTTP 延迟测试（真连通性）

为了获取真实的连通状态，很多高级客户端（如 Clash、v2rayN）提供了“HTTP 延迟测试”或“真连接测试”。
它的原理是：让你的设备通过这个节点，去真实地访问一次特定的网站（通常是 Google 或特定的测试页面），只有当整个链路（你 -> 节点 -> 目标网站）都走通，并获得 HTTP 响应（如 204 无内容）时，才算测试成功。
**建议：** 在客户端中将测速 URL 更改为 `http://www.gstatic.com/generate_204`，以获得最真实的节点可用状态。

## 如何排查节点故障？

当你发现节点无法使用时，可以按照以下步骤进行排障：

1. **更新订阅**：最常见的离线原因就是节点信息已经过期，或者服务商更换了服务器 IP。尝试刷新或更新订阅。
2. **检查本地网络**：确保你本地的宽带或移动网络本身是正常的。
3. **更换测试方法**：在客户端内全选节点，执行“真连接测试”或“HTTP 测速”，剔除那些“假在线”的节点。
4. **选择优质的线路服务**：频繁遇到节点离线或假在线，通常是因为使用的是免费或质量低劣的服务。寻找高质量、稳定在线的节点，根本在于选择[靠谱的网络服务商](/blog/reliable-network-providers)，他们会有专业的运维团队保障服务器的出口连通性，避免“假在线”的困扰。

## 常见问题解答 (FAQ)

**Q1：节点的延迟越低越好吗？**
A：不一定。低延迟代表你到节点的物理距离较近（例如香港、日本节点），但如果该节点带宽太小，看视频依然会卡顿。速度和延迟同样重要。

**Q2：为什么所有的节点突然全部显示“超时”？**
A：如果所有节点同时超时，通常不是节点本身的问题，而是你的本地网络出现故障，或者客户端的系统代理/虚拟网卡设置冲突，建议重启客户端或电脑。

**Q3：什么是“真连接”测试？**
A：真连接测试（URL Test / HTTP Test）是通过节点去实际访问一个网页并测算所需时间，它能 100% 反映该节点是否能正常访问目标网站，比普通的 TCP Ping 更加准确。
