在 macOS 系统中安装并非来自 Mac App Store 的第三方客户端时，用户常常会遇到“无法打开，因为无法验证开发者”或者“文件已损坏”的警告提示。这是 macOS 内置的安全机制在起作用，旨在防止恶意软件的运行。今天就来详细讲解如何通过系统设置安全放行这些应用程序。

## 常见提示类型分析

macOS 通常会抛出以下几种安全提示：
1. **“无法打开，因为无法验证开发者”**：应用没有 Apple 颁发的合法开发者证书，或者系统无法连接到 Apple 服务器进行验证。
2. **“文件已损坏，你应该将它移到废纸篓”**：这通常不是文件真的损坏，而是 macOS 的隔离属性（Quarantine）或者应用签名存在问题。

## 解决方法指南

### 针对“无法验证开发者”

遇到这种情况，我们可以手动在“系统设置”中进行授权。

1. 打开屏幕左上角的 **苹果菜单 ()**，选择 **系统设置** (在旧版系统中称为“系统偏好设置”)。
2. 点击侧边栏中的 **隐私与安全性**。
3. 向下滚动到 **安全性** 部分。
4. 你会看到一条提示，显示刚刚被阻止打开的应用程序名称。点击旁边的 **仍然打开** 按钮。
5. 系统可能会要求你输入 Mac 的登录密码或使用触控 ID 进行验证。
6. 验证完成后，再次尝试打开该应用程序，点击“打开”以确认。此后，该应用便会被加入白名单，不再触发此警告。

### 针对“文件已损坏”提示

如果系统提示文件已损坏并建议移到废纸篓，通常是因为该应用被系统标记为隔离状态 (com.apple.quarantine)。我们可以通过终端（Terminal）命令移除该属性。

1. 打开 **终端** 应用程序（可以在“启动台” -> “其他”中找到，或使用 Spotlight 搜索“终端”）。
2. 在终端中输入以下命令，但**先不要按回车**（注意末尾有一个空格）：
   ```bash
   sudo xattr -r -d com.apple.quarantine 
   ```
3. 打开“访达”(Finder) 中的“应用程序”文件夹，找到提示损坏的客户端应用程序。
4. 将该应用程序的图标拖拽到终端窗口中，终端会自动补全该应用的路径。最终的命令看起来会像这样：
   ```bash
   sudo xattr -r -d com.apple.quarantine /Applications/YourApp.app
   ```
5. 按下回车键执行。
6. 终端会提示你输入管理员密码（输入时密码不会显示，这是正常的），输入完毕后按回车。
7. 命令执行完成后，重新尝试打开该应用程序即可正常运行。

## 安全建议

虽然通过上述方法可以放行第三方应用程序，但请务必确保你的客户端是从可信赖的官方渠道获取的。盲目放行来源不明的应用可能会给你的网络连接环境和数据安全带来风险。
